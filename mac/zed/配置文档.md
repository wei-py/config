# Zed 配置：保留偏好，不携带账户

## 文件与关键开关

| 文件/字段 | 含义 |
| --- | --- |
| `config/settings.json` | JSONC 用户设置，包含 UI、语言、终端和 agent |
| `config/keymap.json` | 按 context 条件分发的自定义动作 |
| `config/themes/nvim-nightfox.json` | 原 Nightfox 0.10.6 主题资产，保留 author 元信息 |
| `nightfox-source.toml` | 上游扩展版本/仓库来源，不安装到扩展目录 |
| `helix_mode` / `vim_mode` | true / false，不是两套同时启用 |
| `theme.mode` | light；浅色 Gruvbox Light Soft、深色 Carbonfox - opaque |
| `format_on_save` | off；TS/JS/Vue 还单独设 formatter=[] |
| `agent.tool_permissions.default` | allow，继承原配置，有执行工具风险 |
| `terminal.shell.program` | /bin/zsh，macOS 系统路径 |

UI 字号18.5、正文17、终端18；正文使用 FiraMono Nerd Font Propo，中文后备 LXGW WenKai Mono GB。相对行号、minimap、sticky scroll、inline diagnostics 与参数 inlay hints 开启。Git 面板左侧，outline 右侧，终端底部。

## 修改建议

命令面板用 `zed: open settings`、`zed: open keymap` 编辑新机真实配置；查看默认项用 `zed: open default settings`、`zed: open default keymap`。应用升级后遇到不支持的字段应对照当前默认设置，不要使用严格 JSON formatter 丢掉 JSONC 注释。

键位一定写到正确上下文。本包保留历史 Vim 上下文项及重复的 j k 规则，以忠实迁移为准，没有擅自重设计。唯一显式 Helix 普通模式自定义块用 `vim_mode == helix_normal`，r r 映射 `vim::HelixJumpToWord`，G 映射 `vim::EndOfDocument`。动作名称中的 vim 前缀不意味着必须开启 vim_mode。

## AI 与项目依赖

`language_models.openai_compatible.MIMO_TOKEN` 是 provider 名称，不是 API Token 本体；其 api_url 是 `https://token-plan-cn.xiaomimimo.com/v1`，模型名 `mimo-v2.6-pro`。默认对话、inline assistant、提交信息与摘要都指向它。新机需要手动提供凭据或把这些引用一起改为自己的模型，否则只改默认模型会留下旧引用。

agent_servers 的 registry 项和 BrowserOS context_servers 都依赖独立软件/服务。没有服务时可禁用对应 MCP enabled 项；更改端口时同步两端。不要把密钥或访问令牌提交到此目录。包含 `.env*` 的文件扫描设置和 agent 默认允许工具需由使用者在可信项目中评估。

Vue 文件关联包含 `.vue`、`.uvue`，TypeScript 包含 `.uts`；这只是语言识别关联，不保证第三方框架完整语义支持。语言服务器/ESLint/项目依赖需由新机网络和项目环境提供。

## 迁移差异与恢复

原 settings/keymap 保持实际行为，另将已安装扩展中的 Nightfox 主题复制到用户 themes/，避免深色外观只依赖旧机扩展目录。来源见 `nightfox-source.toml`；若后续公开分发第三方资产，应按上游仓库的授权要求保留许可。没有打包备份设置、conversations、prompts、扩展缓存、聊天数据库、认证信息和私钥。新电脑登录、模型计费、MCP 服务与系统授权不是复制配置能够迁移的内容。

安装脚本先移动旧目录到唯一备份，再完整复制 config/，不会把旧文件混进新配置。若需恢复，退出 Zed 并用备份目录整体替换。配置有误先从应用日志和设置诊断找真实字段错误；主题找不到时先检查 themes/ 是否随目录一起安装。
