# Zed 操作：编辑器与项目面板分工

本包启用 `helix_mode: true`、`vim_mode: false`，基础 keymap 仍是 VSCode。不要把所有带 `vim_mode` 上下文的旧绑定都当成当前模式下必定生效的键；Zed 不同模式的上下文不同。

## 始终值得记住的键

| 区域 | 快捷键 | 实际动作 |
| --- | --- | --- |
| 通用 | Ctrl+Tab / Ctrl+Shift+Tab | 当前 Pane 下一个 / 上一个 Item |
| 通用 | Cmd+E / Alt+E | 切换项目面板焦点 |
| 项目面板，非重命名输入中 | n / a | 新文件 / 新目录 |
| 同上 | r / d / o | 重命名 / 删除 / 发送 Enter 打开 |
| 通用 | Cmd+K 然后 Cmd+K | 折叠项目树全部条目 |
| 编辑器，Helix 普通模式，无菜单 | r r | Helix 单词标签跳转 |
| 同上 | G | 文件末尾 |
| 通用内置 | Cmd+Shift+P | 命令面板，可搜索配置和动作 |

Ctrl+Tab 是 Zed 当前 Pane 的 Item 导航，不是 Herdr 的跨所有 Workspace/Pane 循环。配套 Hammerspoon 的全局 Cmd+1/2 会发送这两组 Ctrl 键，覆盖 Zed 自己的 Cmd+数字行为。

## 配置保留的其他上下文绑定

| 精确上下文 | 自定义键 |
| --- | --- |
| `VimControl && !menu` | H/L → 行首尾；q q → Format |
| `Editor && vim_mode == insert` | j k → NormalBefore |
| `Editor && vim_mode == visual` | j k → NormalBefore；Ctrl+Enter / Cmd+Enter → InlineAssist |
| `Editor && vim_mode == normal && !menu` | t t → 折叠函数体；Ctrl+Enter / Cmd+Enter、s s → InlineAssist |
| `Terminal` | 解除该上下文中 Ctrl+Enter 的 InlineAssist 绑定 |
| `!AcpThread > Editor && mode == full` | 解除该上下文中 Ctrl+Enter 的 InlineAssist 绑定 |

以上是文件中真实存在的规则，不代表 Helix 普通模式会匹配 `vim_mode == normal`。需要确认时，命令面板搜索 key context/keystroke 调试动作观察当前上下文，再改规则；不要为了“让文档看起来一致”随意换成 Vim 模式。退出编辑插入状态可用 Escape，未确认 j k 上下文时不要只依赖它。

## 日常工作流

1. 打开项目，用 Cmd+E 在树与编辑器之间切换，n 新文件、r 改名，操作前看清面板是否处于编辑输入状态。
2. 编辑器里 r r 做快速跳转。多个文件用 Ctrl+Tab 切换；要查所有动作时走命令面板。
3. 格式化用命令面板的 Format，只有上下文匹配时 q q 才会命中本包映射。全局保存格式化为 off，TS/JS/Vue formatter 列表明确为空，不要期待保存后自动跑 Prettier；这些语言保留 ESLint code action 配置。
4. AI 面板默认为 ask profile、模型 MiMo；新电脑先补凭据。`use_modifier_to_send` 开启，发送方式以面板提示为准。工具默认 allow 不等于只读安全沙箱。

若键位不生效，先检查焦点区域、菜单是否打开及上下文，不要只检查键名。字体异常核对字体族名称；终端程序路径是 macOS 的 `/bin/zsh`，Shell 环境仍来自新电脑，并没有搬走旧机 Shell 配置。
