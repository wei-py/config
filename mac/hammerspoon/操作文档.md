# 操作：先按住 Caps，再按动作键

## 操作层不是“点按 Escape、长按 Hyper”

本配置启动时通过 `hidutil` 把 Caps Lock 映射为 F13：F13 **按下立即**进入模态，松开立即退出。没有 Caps 点击时长判断、没有等待阈值，单击 Caps 只会进入再退出，不发送 Escape、不切换大小写，也不切输入法。先按住 Caps 再按下表中的键；只有明确支持重复的操作会随系统键盘重复节奏连续触发。这里的 Caps 操作层不等价于 Ctrl+Alt+Cmd+Shift。

输入法切换实际绑定的是 **Shift**。监听器在 Shift 标志出现时记录时间，消失时若间隔小于 `0.2` 秒、且当时不处于 Caps 模态，就发送 Ctrl+Space。监听不会吞掉原始 Shift 事件；大于或等于 0.2 秒不触发。它没有检查期间是否按过字母或其他键，因此快速 Shift+字母也可能在松开 Shift 时误切输入法；其他修饰键标志变化时也可能重写计时，不能当作严格“只点按 Shift”检测器。系统必须把 Ctrl+Space 配成预期的输入源切换动作；在系统设置 → 键盘 → 键盘快捷键 → 输入法核对，并检查 Spotlight、其他工具是否占用。修饰键事件监听与 Secure Input、系统权限有关。

## 全部主要键位

以下除最后两行外均需按住 Caps，字母按小写键位、无额外修饰键。

| 键 | 实际行为 | 长按重复 |
| --- | --- | --- |
| ↑ 或 A | 当前窗口铺满当前屏幕可用区域，不是原生全屏 | 否 |
| ↓ | 进入 macOS 原生全屏，不是切换开关 | 否 |
| ← / → | 左半屏 / 右半屏 | 否 |
| Tab | 在当前 Space 所属屏幕的 Spaces 列表中循环到下一个 | 否 |
| R | 发送 Cmd+反引号，通常切换同应用窗口 | 是 |
| 9 / 小键盘 9 | 切换 Mission Control | 否 |
| 0 / 小键盘 0 | 切换应用窗口总览 App Exposé | 否 |
| 1 / 小键盘 1 | 发送 Ctrl+Shift+Tab，通常上一标签 | 否 |
| 2 / 小键盘 2 | 发送 Ctrl+Tab，通常下一标签 | 否 |
| 反斜杠 `\` | 投递系统 PLAY 按下事件，请求播放/暂停 | 否 |
| `=` / `-` | 默认输出设备音量 +1 / -1 个百分点，限制 0–100 | 是 |
| H / J / K / L | 发送 ← / ↓ / ↑ / → | 是 |
| D | 发送 macOS `delete`（通常向后删除，不是 Forward Delete） | 是 |
| I | 启动/聚焦 BrowserOS | 否 |
| O 或 U | 通过 bundle ID 启动/聚焦 Herdr | 否 |
| M | 启动/聚焦 NeteaseMusic | 否 |
| B | 启动/聚焦 WeChat | 否 |
| P | 启动/聚焦 HbuilderX | 否 |
| F | 启动/聚焦 Finder | 否 |
| Y | 启动/聚焦 Helium | 否 |
| N | 打开 Herdr，再定位已有 `me` Workspace 的 `1` Tab | 否 |
| **不按 Caps：Cmd+1** | 全局发送 Ctrl+Shift+Tab | 否 |
| **不按 Caps：Cmd+2** | 全局发送 Ctrl+Tab | 否 |

标签键最终意义由前台应用决定，不保证所有应用支持 Ctrl+Tab。全局 Cmd+1/2 即使在不支持标签的应用中也会覆盖原行为；需要原快捷键时，到 `lib/bindings.lua` 删除或更换末尾两条 `hs.hotkey.bind`，再 Reload Config。

## 三个常用工作流

### 编辑、排窗、换桌面

打开编辑器，Caps+← 放到左半屏，切到浏览器后 Caps+→ 放到右半屏。Caps+H/J/K/L 做光标移动，Caps+D 连续删除。需要专注时 Caps+↓ 进入原生全屏；再用 Caps+A 或左右半屏会先请求退出全屏，等待 50 毫秒后改布局。这个固定等待不保证覆盖所有全屏动画，窗口尚在过渡时可待动画结束再按一次。没有焦点窗口时布局操作静默返回。

Caps+Tab 找当前 Space，在所属屏幕列表中循环并提示序号，不是切换应用、也不是跨所有显示器全局轮转。Spaces 调用受 macOS 版本、Mission Control 设置和动画影响。Caps+9/0 直接调用总览 API，不依靠系统 Ctrl+↑/↓ 的快捷键设置；仍应排查其他窗口管理器与系统快捷键冲突。

### 小步调音量

按住 Caps 后按 `=` 提高音量，按 `-` 降低；这里的加音量键是等号键，不需要 Shift 打出加号。可持续按住重复调节。HUD 在当前主屏幕底部居中显示百分比和进度，最后一次操作后 1 秒隐藏。音量为 0 或设备静音时显示“静音”并隐藏有效进度条；脚本**不会解除静音或提供静音切换**。没有默认输出设备则不操作；某些 HDMI/数字输出设备不能软件调音量，代码没有对 `volume()` 返回空值做兼容，出现错误时换可调音量设备或禁用这两条绑定。

### 直达 Herdr 工作上下文

先在 Herdr 中手工建立或重命名一个 Workspace 为精确小写 `me`，在它里面建立或重命名 Tab 为字符串 `1`，并避免重名。Caps+N 通过 `dev.herdr.app` 查应用安装路径并前置应用，异步调用应用内 `Contents/MacOS/Herdr ls`，解析返回的 Spaces/Tabs，再按 ID 顺序执行 `space.select`、`tab.select`。它不会新建工作区或标签，也不依赖固定 `/Applications` 路径；运行中重复按 N 会被忽略。缺失、重名、CLI 失败会显示提示。

想使用其他名称，编辑 `lib/bindings.lua` 中 `item.name == "me"`、`item.name == "1"` 及相应提示文案；不要把 Tab 数字当作第几个标签。Herdr 是可选外部应用，本目录不复制其会话或工作区。O/U 只前置 Herdr，无名称要求。

## 遇到不响应时

1. 在 Hammerspoon Console 查看真正错误，不只看成功提示。确认入口和 `lib/` 都安装到了 `$HOME/.hammerspoon`。
2. 重新核对辅助功能；监听 Shift 不正常时核对输入监控、重开 Hammerspoon，退出密码输入等 Secure Input 场景。不要迁移另一台机器的 TCC 授权。
3. 检查系统修饰键设置、Karabiner 等 remapper、键盘固件和 F13 冲突。这里要求系统收到原始 Caps Lock；没有专用 EPOMAKER 固件要求。
4. 若仅应用启动无效，先手动安装并打开对应应用，核对 `launchOrFocus` 名称。若仅 N 失败，检查 Herdr 版本、精确名称和提示中的 CLI 错误。
5. 停用时先正常退出 Hammerspoon，退出回调会清空 UserKeyMapping。异常退出可能没执行回调；确认无其他映射要保留后才手动执行 `hidutil property --set '{"UserKeyMapping":[]}'`。该命令会清空整个用户映射，不是只移除 Caps 项。

本配置监听键盘修饰状态、控制前台窗口、调用音频和应用 API，但没有写入按键日志或上传逻辑。`hs.ipc` 会加载本机 IPC 接口；不要将 Console 或 IPC 访问权交给不可信程序。安装不会迁移登录项，若要开机使用请在新 Mac 自行设置 Hammerspoon 登录启动。
